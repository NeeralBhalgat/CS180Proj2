Part 1.1

Convolutions from Scratch

I wrote the convolution manually in two different ways. The first version I wrote uses four nested loops: two loops that move across the image, followed by two more loops that iterate across every (kx, ky) pixel in the kernel. The second version still loops over the image pixels, but we extract the matching image patch and compute the entire kernel in one shot using vectorized operations. For both implementations, I flipped the kernel before applying it. If we didn't flip the kernel, this would have been a correlation operation and not convolution.

I used zero padding so that the output image keeps the same height and width as the input. To check that my code was doing the same operation as SciPy, I compared my box-filtered result against scipy.signal.convolve2d with mode="same", boundary="fill", and fillvalue=0. Both manual versions matched the SciPy output. 

def firstconvimp(img, kernel):
    flippedkernel = np.flip(kernel)
    paddedimg = np.pad(img, ((kH//2,kH//2),(kW//2,kW//2)), mode="constant")

    for x in range(H):
        for y in range(W):
            total = 0
            for kx in range(kH):
                for ky in range(kW):
                    total += paddedimg[x + kx, y + ky] * flippedkernel[kx, ky]
            output[x,y] = total
def secondconvimp(img, kernel):
    flippedkernel = np.flip(kernel)
    paddedimg = np.pad(img, ((kH//2,kH//2),(kW//2,kW//2)), mode="constant")

    for x in range(H):
        for y in range(W):
            portion = paddedimg[x:x+kH, y:y+kW]
            output[x,y] = np.sum(portion * flippedkernel)

The second implementation is cleaner because we automatically compute the result through vectorized multiplication and sum operations. We are able to get rid of the inner two kernel loops as a result. In terms of runtime, the four-loop version is the slowest, followed by the two-loop version, and the SciPy convolve2d function is the fastest.

The derivative filters behaved as expected. The X derivative filter led to strong vertical changes in the output image. The Y derivative filter led to strong horizontal changes in the output image.

Part 1.2

Finite Difference Operator

For the cameraman image, I applied the following convolutions: D_x = [1, 0, -1] and D_y = [1, 0, -1]^T. We can see that these derivative filters show the intensity changes in the image, allowing us to see some of the prominent edges. After applying these convolutions, I combined them into a gradient magnitude image using sqrt(dx^2 + dy^2).

To turn the gradient magnitude into an edge image, I tried many different thresholds. I realized that with lower thresholds, the image felt more noisy since some of the weak texture changes in the grass and background were being highlighted. A high threshold helped solve this, but if the threshold was too high, then there was a chance some edges would not be highlighted anymore. I tried several thresholds and settled on 0.20. I chose this threshold because it preserves the main silhouette, camera, tripod, and building edges while removing many of the isolated grass and background responses. However, it is not perfect and some faint edges are lost. This was the best tradeoff to me between finding real contours and not labeling too much noise as an edge.

Part 1.3

Derivative of Gaussian Filter

The finite difference result was sensitive to the threshold because the x and y derivative filters respond to small intensity changes and noise. As a result, the next step was to smooth the image before taking derivatives to remove some of the noise. I used OpenCV's 1D Gaussian kernel and multiplied it by its transpose to make a 2D filter. I convolved the cameraman image with this filter and then repeated the same steps from Part 1.2.

The blurred version is much cleaner. The edges are thicker because the Gaussian blur smooths out each pixel based on its center and neighbors, which reduces some of the noise. The random-looking speckles are reduced a lot after smoothing.

Because convolutions are associative and commutative, we also convolved the Gaussian filter with D_x and D_y directly. Then we applied this to the image and got the same result.

Overall, smoothing before edge detection made the output easier to read. The finite difference image is sharper but responds to noise and is not as clean. The lower half of the image is a lot cleaner and more well-defined with the derivative of Gaussian filters.

Part 2.1

Image Sharpening

Unsharp masking works by first blurring the image to remove high-frequency details. Then I subtract the blurred image from the original image to get the high frequencies, which are mostly edges and fine details. Finally, I add some amount of those high frequencies back to the original image using an alpha constant to make the image look sharper. In code, the main step was sharpened = image + alpha * (image - blurred).

I used a 9 by 9 Gaussian filter with sigma 1. After experimentation, I realized these parameters kept the blur strong enough to separate edges from smoother regions without completely washing out the image.

The Taj Mahal example shows the sharpening most clearly. The dome and windows look sharper. There is much more local contrast in this new image. This makes the image look more prominent, but if the image looks too harsh compared to the original, it comes off as artificial, which is a tradeoff.

I also tried different alpha values on the flower image. A small alpha kept the result close to the original. Larger alpha values made the textures, edges, and small features like the raindrops stand out more. With alpha = 10, the petals look too folded and crunchy, and the center is too intense in relation to the petals. Thus, the image starts to feel less natural.

The overall pattern was pretty consistent: sharpening helps when the image has good texture or clean edges. Pushing alpha too far makes the result look overprocessed instead of sharper though.

Part 2.2

Hybrid Images

To make the hybrid images, I combined the low frequencies from one image with the high frequencies of another image. I used the alignment code to line up the corresponding points, usually the left eye and right eye.

The low-frequency image is the one that should dominate from far away, so I blurred it with a Gaussian filter. The high-frequency image is the one that should be visible close up, so I subtracted the blurred version of it from the original. I used a 9 by 9 Gaussian kernel with sigma1 = 5 for the low-pass image, and sigma2 = 4 for the high-pass image. I chose these cutoff values after testing smaller and larger sigmas. Smaller values left too much high frequency texture in the low pass image. Larger values made the high pass layer too weak and washed out. My initializations kept the broad face structure visible from far away while preserving enough of Einstein's hair, wrinkles, and mustache up close. Hence, I thought this was a good tradeoff.

I think this is my clearest hybrid result. From far away, the broad structure comes from my selfie. Up close, you can see Einstein's crazy hair, wrinkles, and mustache. The Fourier plots reinforce this idea: the low-frequency image has most of its energy concentrated near the center, while Einstein contributes more fine detail away from the center.

The other two examples also turned out well.

Part 2.3

Gaussian and Laplacian Stacks

For this part, I built Gaussian and Laplacian stacks. We use stacks instead of pyramids because we do not need to downsample, and we can keep every image at the same size, with each level just being a more blurred version of the previous one. The Gaussian stack at each level contains a more blurred version of the image. The Laplacian stack stores the detail that disappears between neighboring Gaussian levels. I used four levels. The first row contains the finer detail, and the final row contains the low-frequency base that is kind of the foundation of the image. For the Oraple column, I took the left half from the apple Laplacian level and the right half from the orange Laplacian level and merged them together. The Gaussian stack shows the same images becoming smoother at each level without changing size, and the Oraple Gaussian column uses a vertical half-and-half mask.

The Laplacian stack below isolates what disappears between neighboring Gaussian levels. This is the version used to reconstruct the blended image from its fine detail all the way up to the general base details.

Part 2.4

Multiresolution Blending

For Part 2.4, I worked on multiresolution blending. Part 2.3 showed that the Laplacian stack is useful because it stores image detail at different scales. For blending, I realized that we need to use the same stack idea, but instead of cutting each level using a hard mask, we can make a Gaussian stack for the mask. That way, the original mask can be sharp, but the blurred mask levels make the transition wider at coarser frequencies, which is what removes the obvious split between the photos.

I first tested the method with the classic apple and orange example. The mask is a simple step function because it is a vertical seam mask. The left half is one, so it comes from the apple. The right half is zero, so it comes from the orange. The Gaussian stack of the mask softens the transition near the middle instead of having a hard seam cut.

After the Oraple worked, I tried two irregular masks. The first mask is a wavy irregular mask between a zebra and a horse.

For my second irregular blend, I switched to two flowers on dark backgrounds, and I used an irregular blob mask.

The blob mask is not a simple line. Its boundary changes with angle, and it is created using sinusoidal perturbations. I've shown the stack levels below so that you can see how the fine details, mid-level details, and coarse base are reconstructed overall.

The main thing I noticed is that the mask matters as much as the images. A rigid mask can look like it is dividing the images, and a good mask can give the blended effect.
